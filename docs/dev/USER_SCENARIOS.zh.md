# 用户场景(pi-tree 定制版)

> 本文档记录本项目的目标用户与核心使用场景,是开发计划的依据。
> 配套文档:设计思想见 `DESIGN_PRINCIPLES.zh.md`,开发计划见 `DEV_PLAN.zh.md`。

---

## 目标用户

- **科研人员 / 学生**:需要精读学术论文(以 arXiv PDF 为主),经常遇到"文章假设了我不懂的背景知识"的情况;
- **中文使用者**:希望 AI 用中文讲解,但保留英文术语原文;
- **自托管用户**:数据放在本机(SSD),不带云,自带 API Key(DeepSeek 为主)。

## 核心场景:精读一篇论文

### 场景 1 — 导入论文
用户打开应用,把一篇论文加进书架,两种方式:
- 上传本地 PDF 文件;
- 粘贴 arXiv 链接 / ID,系统自动抓取并归档原始 PDF。
系统在后台提取全文与章节结构,生成目录。

### 场景 2 — 看原文(真 PDF 渲染)
用户点击论文,在阅读界面以**原版 PDF 排版**查看页面(公式、图表、双栏原样显示),支持:
- 连续滚动、缩放、翻页;
- 左侧章节树(来自 PDF 内嵌目录),点击跳转到对应页;
- 页面文字**可选中、可复制**。

### 场景 3 — 划词提问
用户在 PDF 页面上选中一个术语 / 一句话,弹出浮动工具栏:
- **提问**:预填聊天输入框(带原文引用);
- **查词**:右侧词典面板解释该术语;
- **开分支**:以引用原文的形式在树中开一个新分支讨论;
- **存备忘**:保存为 memo 供日后检索。
提问会携带 `{页码, 原文摘录, 所在章节}` 上下文,保证 AI 回答精确落地。
**答案的来源构成(重要)**:不只是一字不差复述论文,而是三层——
① 论文本身怎么说的(标注章节/行号);② 背后的原理、定义、推导(LLM 知识,并注明"这是通用原理");③ 外部可信来源怎么说(权威教材、著作、arXiv 相关研究,带链接)。每条关键论断都标注来源,论文观点与外部解释不混淆。

### 场景 4 — 划章节提问
用户在章节树上选中某一节(如 "3.2 Training Objective"),点击 **"就此节提问"**:
- PDF 视图跳转到该节起始页;
- 提问自动带该节标题 + 首句摘录 + 页码范围;
- 可以问"这一节的核心假设是什么""这个公式怎么推导"。
- 回答同样遵循多源构成:先准确转述该节内容,再补充原理性解释与外部可信来源(带出处)。

### 场景 5 — 回答中继续追问
AI 给出回答后,用户对回答里的任何一点不满意或想深挖,直接在**该回答下方**开分支继续追问:
- 追问只携带"根→当前回答"的路径上下文,不污染其他分支;
- 例如:回答提到 "anchoring bias" → 追问 "它和 System 1 的关系?" → 再追问 "论文里哪一节验证了这个?"。

### 场景 5b — 在 AI 回答里划词开分支(对话内容锚点)
用户直接**选中 AI 回答中的一句话 / 一个术语**:
- 弹出工具栏:以此为锚点开分支提问(引用该回答片段)、查词、存备忘;
- 新分支的锚点记录为"对话内容锚点"(哪条回答 + 选中片段),而不是 PDF 页码;
- 回溯时:点击该节点 → 恢复问答上下文,并**在聊天区滚动到那条回答、高亮当时选中的片段**;
- 与 PDF 划词开分支对称:树既可以"从原文长出来",也可以"从对话内容长出来"。

### 场景 6 — 理解后返回上一层
深挖完分支,用户通过**面包屑**或**左侧树导航**回到上层,继续看刚才的回答:
- 回到上层后,之前的分支内容仍在树上,随时可再进去;
- 不同分支互不污染,模型上下文保持干净。

### 场景 6b — 点击历史节点,回到锚点位置
用户点击树中任意一个历史提问节点:
- 问答上下文切换到该分支(看到当时的提问与回答);
- **按锚点类型定位**:原文锚点 → PDF 面板自动跳到锚点页并高亮选中原文;对话内容锚点 → 聊天区滚动到对应回答并高亮选中片段;
- 相当于"我当时是看到这句话才问的"——想不起来上下文时,直接回到原处再读。

### 场景 6c — 导出阅读记录
用户把一次论文阅读的完整"对话树 + 锚点"导出为 JSON(可移植格式):
- 每条记录含 question/answer/锚点(页码+原文+章节)与父子关系;
- 未来可在 Zotero 插件里打开同一份记录,继续读、继续问,不用迁移聊天历史。

### 场景 7 — 回复语言偏好
用户在设置里选择 AI 回复语言:
- **跟随提问**(默认):中文提问 → 中文回答,英文提问 → 英文回答;
- **强制中文 / English / 其他**:无论怎么问,都按选定语言回答;
- 会话内可临时切换,覆盖全局默认;
- 术语策略:保留英文原文并附中文释义。

### 场景 8 — 配置(不碰配置文件)
首次使用,用户打开设置页:
- Provider 默认 **DeepSeek**;
- 粘贴 API Key(界面只回显尾 4 位);
- 保存即生效,全程不需要打开 `.env` 或编辑 JSON。

---

## 非目标(明确不做)

- **全站中文界面**:界面保持英文,只做"AI 回复语言可选"(已确认);
- **扫描版 PDF 的 OCR**:无文本层的页面提示"不可选择文本",不做识别;
- **多用户 / 云服务**:保持 local-first 单用户形态;
- **改写核心树模型**:树状会话引擎(Pi SDK)不动,只在其上扩展。
